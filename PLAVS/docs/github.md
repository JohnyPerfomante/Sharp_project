# Публікація проєкту на GitHub

## Готовий комплект

Для публікації потрібні вихідний код і файли відновлення середовища: `src`, `tests`, `tools`, `database`, `scripts`, `docs`, маніфест у `models`, solution, конфігурація Docker та приховані службові файли. Повна інструкція користувача збережена в `docs/user-guide` у форматі DOCX.

Скрипт формує окрему папку з потрібними файлами, перевіряючи кількість і розмір:

```bash
python3 scripts/package.py --directory ../PLAVS-GitHub
```

Цільова папка має ще не існувати: скрипт захищає наявні файли від перезапису. Поряд також створюється `PLAVS-GitHub.zip`; після розпакування він містить папку `PLAVS` із тим самим комплектом. Скрипти перевірки й пакування працюють у звичайній розпакованій папці без `.git`.

## Завантаження через сайт

1. Створіть порожній репозиторій на GitHub. Якщо створюєте його для цього комплекту, не додавайте початковий README автоматично.
2. Відкрийте **Add file → Upload files**.
3. Перетягніть **вміст** чистої папки `PLAVS-GitHub` у корінь репозиторію. Якщо користуєтеся ZIP, спочатку розпакуйте його.
4. Перевірте, що серед файлів є `README.md`, `PLAVS.sln`, `Dockerfile`, `compose.yaml`, `.env.example`, `.gitignore`, `.dockerignore`, `.github` та `.config`. У Finder на Mac приховані файли показує **Command + Shift + крапка**. Назви папок і вкладені шляхи потрібно зберегти.
5. Натисніть **Commit changes**. Після завантаження README має відкриватися на головній сторінці репозиторію.

Сайт GitHub приймає до 100 файлів за одну операцію та до 25 MiB на файл. Комплект перевіряється із запасом: до 100 файлів і до 20 MiB на файл. [Офіційні обмеження завантаження](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## Завантаження через Git

Для подальших змін зручно користуватися Git або GitHub Desktop. У корені проєкту виконайте:

```bash
git init
git add .
git commit -m "Add PLAVS application"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Підставте адресу власного репозиторію. Якщо `origin` уже налаштований, скористайтеся ним. Локальна `.env`, модель і згенеровані збірки виключені через `.gitignore`.

## Що відновлюється після завантаження

На іншому комп’ютері встановіть Docker Desktop і Python 3.10+, запустіть Docker Engine, відкрийте термінал у корені завантаженого проєкту й виконайте:

```bash
python3 scripts/docker-start.py
```

Скрипт створить локальну конфігурацію, перевірить модель у `~/.cache/plavs/models/<ревізія>`, за потреби завантажить її, збере застосунок та запустить PostgreSQL і API. Відкрийте `http://localhost:5080`.

NuGet відновлює бібліотеки за `.csproj` і `packages.lock.json`. Міграції та JSON-наповнення відновлюють структуру й навчальні дані нової бази. Для перенесення наявних робочих записів окремо використовуйте `database/scripts/backup.sh` і `restore.sh`.

## Локальні файли

| Файли | Де зберігати | Як відновлюються |
|---|---|---|
| `model.onnx`, `tokenizer.json` | Локальний кеш поза проєктом та Docker volume | `scripts/download-model.py`; `docker-start.py` імпортує в контейнер |
| `bin`, `obj`, бібліотеки виконання | Кеш збірки або локальні ігноровані папки | .NET і NuGet; Docker збирає їх усередині образу |
| `.env` і власні паролі | Локально, поза публікацією | `scripts/setup.py` створює нову конфігурацію |
| Робоча PostgreSQL та резервні копії | Docker volume та приватне резервне сховище | Окреме резервування й відновлення |
| Логи, результати перевірок і проміжні знімки | Окрема локальна папка | Генеруються під час відповідної операції |

Перевірка перед публікацією:

```bash
python3 scripts/check-repo-size.py
```

Для чистої папки можна перевірити саме всі фізичні файли, включно з тими, що зазвичай ігноруються:

```bash
python3 scripts/check-repo-size.py --physical
```
