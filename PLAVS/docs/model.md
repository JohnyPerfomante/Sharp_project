# Локальна семантична модель й алгоритм

## Походження

Використовується [sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2), ревізія **`e8f8c211226b894fcb81acc59f3b34ba3efd5f42`**, Apache-2.0. Джерело публікує багатомовну модель для 50 мов, включно з українською; підтримка мови не є гарантією якості оцінювання фахових знань.

Джерело експорту: `onnx/model.onnx` у тому самому офіційному репозиторії. Завантажується FP32 CPU-граф, придатний для різних архітектур, без залежності від AVX-специфічної квантизації. Manifest містить точні розміри й SHA-256:

| Файл | Розмір, байтів | SHA-256 |
|---|---:|---|
| model.onnx | 470301610 | `10f7a088420252b26caf819236ca2c9d2987afd0fc06fec7553b542a5655a05a` |
| tokenizer.json | 9081518 | `2c3387be76557bd40970cec13153b3bbf80407865484b209e655e5e4729076b8` |

Скрипт використовує тимчасовий файл, перевіряє розмір і хеш, потім атомарно замінює ціль. Сервіс також перевіряє хеші під час запуску. Для заміни моделі потрібно свідомо оновити manifest, очікувані хеші й версію алгоритму; неперевірена модель не активується мовчки.

Ваги й токенізатор зберігаються поза Git і поза папкою вихідного коду: за замовчуванням `~/.cache/plavs/models/<ревізія>`. Команда `python3 scripts/download-model.py --print-directory` показує точний шлях. Скрипт завантаження, API й утиліта `PLAVS.Evaluate` використовують цей кеш. Для іншої папки задайте `PLAVS_MODEL_DIRECTORY`; API також підтримує `Model__Directory`, а утиліта — `--model-dir`. У Docker шлях задає `Model__Directory=/app/models/onnx`, і файли читаються з named volume. `scripts/docker-start.py` автоматично перевіряє та імпортує їх із кешу.

## Токенізація та інференс

1. Application передає нормалізований текст: Unicode FormKC, нижній регістр, уніфіковані апострофи, тире та пробіли. Заперечення не видаляються.
2. `Microsoft.ML.Tokenizers 3.0.0` читає **повний офіційний tokenizer.json** через `SentencePieceTokenizer.CreateFromTokenizerJson`.
3. Його модель — Unigram з 250002 словниковими елементами, Precompiled normalizer, WhitespaceSplit + Metaspace (`▁`, prefix space). Postprocessor додає `<s>=0` і `</s>=2`; `<pad>=1`, `<unk>=3`.
4. Межа — **128 токенів разом зі спеціальними**, як у `sentence_bert_config.json` джерела. При перевищенні зберігається початок і фінальний `</s>`; формується попередження й обов'язкова ручна перевірка.
5. Вхід — Int64 `[1, sequenceLength]`: `input_ids`, `attention_mask`, за наявності `token_type_ids` з нулями. Один запит має динамічну довжину без padding.
6. Вихід — `[1, sequenceLength, 384]`. Виконується mean pooling токенів з урахуванням attention mask. Оскільки padding не додається, усі елементи маски дорівнюють 1.
7. Вектор нормалізується за L2. Косинус обмежується до [0;1]; від'ємна близькість відповідає 0.

ONNX-session створюється один раз; CPU має 2 intra-op потоки й 1 inter-op. Semaphore обмежує одночасний інференс. Embeddings еталонів кешуються на 8 годин у пам'яті, до 2048 записів; ключ включає версію моделі й SHA-256 нормалізованого тексту. Embeddings студентських відповідей не кешуються між аналізами.

`database/seed/tokenizer-golden.json` містить контрольні ID, отримані офіційним Hugging Face `tokenizers 0.22.1` для цього tokenizer.json. Перевірено повний збіг чотирьох українських рядків, апострофів, регістру, пробілів і C#/C++. Для відтворення сирих ID: `dotnet run --project tools/PLAVS.Evaluate -- --tokens "Ваш тестовий рядок"`.

## Інші складові

**L:** FuzzySharp `0.5 × Ratio + 0.3 × TokenSortRatio + 0.2 × TokenSetRatio`, поділено на 100. Повне рядкове порівняння зменшує переоцінювання коротких фрагментів.

**K:** для кожного поняття перевіряються термін і затверджені викладачем синоніми на межах токенів. Короткі слова та скорочення потребують точного збігу; слова від 5 символів допускають Fuzzy Ratio ≥84 при різниці довжини ≤2. Це обмежена евристика для форм слів і друкарських помилок, а не повний морфологічний аналіз. Для надійного покриття викладач має додавати потрібні словоформи до синонімів.

`K = Σ(wᵢ × pᵢ) / Σwᵢ`. Виявлене поняття поруч із запереченням не зараховується автоматично й отримує ознаку `negated`. Правило трьох попередніх токенів може дати хибне попередження; воно не доводить суперечність.

**S:** `100 × (0.25L + 0.55M + 0.20K)` за початкових налаштувань. Кожен активний еталон і погоджена варіація отримують **власну повну трійку** L/M/K; обирається кандидат з найбільшим S. Незалежні максимуми L і M не змішуються.

Початкові категорії: High ≥80, Partial ≥55, Low <55. Low і Partial, заперечення, усічення, відсутні поняття з K<0.6 або відсутність моделі спричиняють ручну перевірку. High залишається попередньою відповідністю, а не остаточним рішенням викладача.

ML.NET створює реальні текстові features через `FeaturizeText`; це окремий компонент для майбутнього навчання/калібрування. Він **не підмінює** семантичний M та не подається як уже навчений класифікатор.

## Відмови й межі

За відсутності, неправильного хешу або збою ONNX обчислюються лише доступні L і K; **M=null, S=null**, категорія Unavailable, стан NeedsReview. Ваги не перерозподіляються, випадкові оцінки не генеруються. Технічна неочікувана помилка зберігає AnalysisError для повторного запуску.

Подібність не гарантує істинності. Ця версія не є формальним перевіряльником фактів або повним детектором заперечень. На контрольній вибірці зафіксовані проблеми з перефразуваннями; потрібні експертні категорії, аналіз хибних рішень та окрема перевірка після калібрування. [Фактичні вимірювання](verification.md).
